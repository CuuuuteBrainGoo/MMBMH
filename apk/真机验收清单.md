## 39. v1.6.3：单张扫描「识别无异常直接入账」（2026-09-28）

> 起因：少爷问「两张票都是单独扫的、没有错误提示，为什么不直接入账、还要手动确认」。
> 查下来这**不是有意的设计取舍，是接线漏了** ——
> 批量导入能一键入账干净的票，单张扫描却必须手点一次；
> 判据（`core/BatchTriage.kt`）明明只有一份，却只接了批量一个消费者。

### 39.1 改了什么

| | |
|---|---|
| **改前** | 单张扫描：识别成功 → **无条件**进核对页 → 必须点「确认入账」 |
| **改后** | 单张扫描：识别干净 → **直接入账** + 弹提示；有问题才进核对页 |
| **判据** | 与批量**完全同一套** —— 无错误、**无警告**、无字段冲突、非重复、非疑似重复 |

> ⚠️ **有警告的票仍然要人看**：比如票面金额和你号码推算出来的对不上，
> 那是一条 WARNING，自动入账会把错账固化进账目。这条边界没有松。

### 39.2 验收项

| R4 | 设置 → 数据备份 → 导出 → 文件非空              | 万一出事这是唯一的退路          |

## 已知限制（提前说明，不是 bug）

### 备份相关

1. **备份要你自己动手导。** 没做「自动定时备份」——  
   真要自动备份，得把文件写到网盘，那涉及账号授权，比手动点一下复杂得多。  
   建议养成习惯：**每次录完一批票，顺手导一次**（也就几秒钟）。
2. **备份文件没有加密。** 里面是你的购彩记录（不含 API Key）。  
   **别随手发到群里**，存网盘的话放自己私人目录。
3. **备份不含 API Key** —— 这是 §17 的硬要求，不是漏了。换手机后到设置里重填一次。
4. **备份不含「AI 调用次数 / token 统计」和未入账的识别草稿** ——  
   那是运行日志性质，丢了不影响账目。恢复后首页那栏 AI 统计会从头计。

### 功能还没做的

**第三阶段的清单已经全部做完了。**（复式/倍投记录、完整手工录入 → 历史文件第 23 组；  
数据备份恢复 → 第 22 组；批量导入 → 第 25 组。）

**v1.4.2 又补上了「分彩种 / 分期号统计报表」**，所以这条也从待办里划掉了。

### 行为上的取舍（都是有意的）

1. **兑奖顺延只覆盖国庆头 3 天和春节头 7 天**，其它法定假日（清明、五一、端午、中秋）不顺延 ——  
   这是少爷明确指定的范围，不是漏了。
2. **春节日期表只做到 2035 年**，表覆盖不到的年份**不顺延**（宁可保守，也算错你的兑奖期限更糟）。
3. **定时核验在省电模式下可能被系统推迟**几分钟到几十分钟。  
   对彩票无影响（公告 21:35 就出），而且**打开 App 会立刻补一次**，不会漏。
4. **一、二等奖金额必须你点一次确认**才计入盈亏 —— 这是交接稿 §15 的硬要求，  
   不是 bug。界面会预填官方公布值，你只需核对后确认。
5. **连通性测试只验「地址 + Key + 模型标识 + 传图格式」四件事，不验「读得准不准」** ——  
   探针传的是 32×32 纯白图，只能证明平台接受 `image_url` 传参，证明不了它读得懂彩票。  
   这一点必须实拍一张票才知道。
6. **豆包用的是推理接入点 ID**，接入点与创建时的区域绑定。  
   以后换区域的话接口地址要跟着改（当前是北京区 `ark.cn-beijing.volces.com`）。
7. 日志内存缓冲上限 500 条，落盘文件 256KB 轮转一次。
