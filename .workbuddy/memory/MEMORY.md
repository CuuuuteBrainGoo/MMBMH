## 版本号（2026-09-27 少爷指出问题后立规）

**唯一来源**：`LotteryLedger/version.properties`（`versionCode` + `versionName`）。
`app/build.gradle.kts` 读它，**不要再把版本号写回 gradle 文件**。

- `versionCode` 每次交付 APK 必须 +1（Android 靠它判断"是不是新版本"）
- `versionName` 语义化：加功能升 minor，只修 bug 升 patch
- `F:\LottBuild\_pack.py` 打包前会读它，跟 `.last_pack_version` 比对，
  **没涨会打印醒目警告** —— 这是防我再忘的守卫

起因：连着迭代七八个版本，APK 里的版本号一直停在 1.1.0。
根因是版本号散落在 gradle 里、每次打包没人检查。**机制问题，不是粗心问题。**

1. 改权威源码
2. `python F:\LottBuild\_build_and_test.py`（同步 + 编译 + 单测，带报告新鲜度校验）
3. **问少爷要不要打包**（见下方新规）
4. `python F:\LottBuild\_pack.py`（版本守卫 → 编译两变体 → 打包 → 签名，带 dex 占用重试）
5. `python F:\LottBuild\_dexprobe2.py`（拆 dex 证实新代码真的进包了）
6. 更新 `apk\真机验收清单.md`
7. 写入 `memory\YYYY-MM-DD.md`

**第 3 步是 2026-09-27 中午新加的规矩**（少爷亲定）：

> 「今后在每次对话或讨论并修正 BUG 后，不要默认直接打包。
> 你应该先反馈改动内容，然后询问我是否需要打包。」

- 例外：**能论证打包对接下来工作有实质帮助**时可以自行决定，
  但必须说明「为什么这次要打」（典型：改动本身只有真机能验）
- 他明确说「打包 / 给我 APK」时直接打，不要再反问

`sync: 0 copied` + `1 executed` 是假成功信号，必须靠拆 dex 或报告时间戳验证。

## 验收清单：只放「当前版本」，历史必须归档 ★（2026-09-27 立规）

少爷 2026-09-27 反馈：「侧边栏的 markdown 真的好卡，打字都费劲」。
实测根因 —— `apk\真机验收清单.md` 已经长到 **115 KB / 1525 行 / 612 个表格行**，
而且**一直挂在侧边栏预览**。表格是 markdown 里渲染最重的东西，
文件常驻 + 界面重绘 = 全文重排，所以连打字都卡。

**根因是我的做法**：连着 5 轮交付都往同一个文件追加验收组，体积只增不减。

**现在的规则**：

| 文件 | 放什么 | 体量红线 |
|---|---|---|
| `apk\真机验收清单.md` | 安装说明 + **当前版本新增表** + **当前版本那一组** + 回归抽查 + 已知限制 + 平台速查 | **≤ 25 KB** |
| `apk\验收清单-历史.md` | 历史各组 + 沙箱实测结论 + 逐版证据 | 随意，但**平时不许打开** |

**每次升版的固定动作**：

1. 把主文件里的「上一版新增表」和「上一版那一组」整段**剪到历史文件末尾**
2. 主文件写入「本版新增表」+「本版那一组」
3. 主文件体积超过 25 KB 就说明忘了第 1 步
4. **`present_files` 时不要把历史文件推给预览** —— 那是 100 KB 的表格墙

一次性拆分脚本留在 `F:\LottBuild\_split_checklist.py`（已执行过，留作参考）。


## 沙箱/工具铁律

- **长任务绝不接管道**（`| tail` / `| head`）：`tail`/`head` 在沙箱里时常不存在，
  管道断裂会让 python 收 SIGPIPE **被中途杀掉**，而退出码显示 127，看不出任务半途而废
- `taskkill` 必须写 `MSYS_NO_PATHCONV=1 taskkill /PID N /F`
- Git Bash 会改写传给 .exe 的 PATH → 需要设 PATH 时在 **Python 脚本内部** `os.environ`
- 批量删除 > 50 文件/轮会被拦；先试 `mv` 改名
- `res/` 目录里**只能放 .xml 和 .png** —— 备份文件（`.bak`）放进去会让 aapt2 直接报错

## 产品规则（交接稿确认过 + 少爷追加确认，不可擅改）

- 不长期保存照片；AI 只负责读票；**程序本地对奖**
- 实体彩票唯一性去重（票身份指纹是唯一可阻止入账的依据）
- 一二等奖金额**必须人工确认**后才计入盈亏（§15）
- 大乐透奖池 ≥8 亿时三至七等奖上调：三 6666 / 四 380 / 五 200 / 六 18 / 七 7
  （六等奖是 **15 / 18**，"20 元"是五等奖升档后的金额 —— 以前记串过）
- 兑奖期限：开奖日 + 60 天；**国庆头 3 天、春节头 7 天**内到期的顺延，其它不顺延
- 春节日期是硬编码表（2025~2035），表外年份**不顺延**（宁可保守）
- 对奖时机：开奖日 **22:30** 跑；没拿到结果 → 次日 **08:30** 再跑；没有待核验的票就不跑
- 入账时若已过开奖时间（当天 22:00 后 / 往日），**当场核验一次**
- 查询范围：官方接口每次拉 **200 期**（约 15 个月）。曾是 50 期，导致 4 个月前的票
  查不到 → 永远卡在"等待开奖结果"（已修）

### 「号码撞大奖」是**玩笑**，不是中奖提示 ★（2026-09-27 少爷纠正）

第 4 条我第一版理解**反了**：
- ❌ 我做的：真中了一二等奖 → 弹庆祝浮层
- ✅ 他要的：**往期买过的号码恰好等于本期开奖号码** → 弹一句损话（"就差一期"）

**为什么必须分清**：那张票是**往期**买的，**根本没中本期的奖**。
所以实现上有三条硬约束：

1. **绝不碰账目** —— 票的状态、金额一点不变（彩蛋跑失败也不能影响任何功能）
2. **文案不许出现「中了 / 恭喜 / 中奖」** —— 否则玩笑变假好消息，比不弹还糟
3. **排除「本期自己买的票」** —— 那是真中奖，走 `PrizeRules` + 奖金确认

实现：`core/JackpotTease.kt` + `MainActivity.TeaseOverlay`
（紫色 `LedgerColors.Tease`，跟中奖红/过期紫/待确认金全部错开）。
冷启动检查一次；同一个（彩种 + 本期期号）只调侃一次，
**没撞上不记录** —— 这样以后新录入的老票还能再撞。

**2026-09-27 第 2 轮追加**：
- **对比范围只用「最新一期」vs「本机全部记录」**，**本机多少期就比多少期**。
  少爷原话：「只用最新的一期号码跟本机号码做对比筛选就可以了，没必要看官方 200 期」。
  ⚠️ 曾误写「官方只给 200 期所以超范围撞不上」——**那句话是错的**，
  200 期限制的只是「官方能给多少期开奖结果」，跟「拿本机历史去比」无关。已从代码注释删掉。
- 浮层**必须点按钮 3 次**才关（点空白处不关）；文案池 20 条随机取。
- **话术红线**：不许出现「中了 / 恭喜 / 中奖 / 发财」——
  单测 `JackpotTeaseTest` 会扫全池，加话术时别踩。

## 过期票：**紫色 + 负号**（2026-09-27 少爷第 2 轮改）

- 颜色：`LedgerColors.Expired` = **紫 `0xFF7B3FA0`**（原是绿，跟 `Spend` 墨绿撞色被换掉）。
  改这一处即全站生效 —— 首页 chip、卡片金额、详情页都走它，`statusColor()` 也指向它。
- 显示：过期金额**必须带 `−` 号**（首页 `HeroStat(negative=true)`、卡片 `过期 −¥xx`）。
  理由：那是**永远拿不到的钱**，不带负号跟「已兑/待兑」并排会被当成资产。

## 统计报表（`core/LedgerReports.kt`）口径 ★

新增「按彩种 / 按期号」聚合。**金额口径必须与首页总账完全一致**：
`purchase` 照算、`prize` **排除 `EXPIRED_UNCLAIMED`**、`expired` 单列。
单测钉了不变量：**各桶净收支之和 = 总账净收支**。改口径时两边一起改，
否则用户会发现「报表加起来对不上首页」。UI 在 `ui/ReportsScreen.kt`，入口是首页右上柱状图。

## 主题模式（`core/ThemeMode.kt`）

LIGHT / DARK / **SYSTEM（默认）**，存 `SettingsStore.KEY_THEME_MODE`。
默认**必须** SYSTEM —— 老用户升级上来行为要跟以前（纯跟随系统）一致。
`LedgerRoot` 结合 `isSystemInDarkTheme()` 算出最终深浅再包 `LedgerTheme`。

## ⛔ 预填值里绝不能出现真实账号资源标识 ★（2026-09-27 立规）

`ProviderDefaults` 里给新用户的**预填值会发给每一个装了这个 App 的人**。

曾发生：`DOUBAO_ENDPOINT_ID` 被填成少爷本人的接入点 `ep-m-xxxxxxxxxxxxxxxx`。
它不是密钥（没 Key 请求只会 401、花不掉钱），但属于**别人的账号资源**。

**规矩**：占位符要一眼假、又能看出格式（如 `ep-xxxxxxxxxxxxxxxx`），
让用户自己去控制台复制。写预填值时先问一句「这个值是不是某个具体人的」。
注释里也不许写真实 ID。

## 帮助页与表单说明的写法（2026-09-27）

- `ProviderDefaults.Template` 带 5 个 UI 用字段：`baseUrlHint` / `modelHint`
  / `keyHint` / `consoleUrl` / `docsUrl`，另有通用 `ProviderDefaults.Hints`
- **每个输入框下方都要有说明**，说清「这是什么、去哪抄、常见坑」——
  少爷的原话是「让没有基础的新用户了解这里填什么」
- 帮助页链接走 `Intent.ACTION_VIEW` **不在 App 内开 WebView**（这些站点要登录，
  塞进 App 更难用）；`documentedKinds` 过滤掉没有官网的 CUSTOM
- 说明行统一走私有 `Hint()` 组件，别裸写 `Text` —— 否则缩进对不齐，像两套界面

## ⛔ 手画 SVG 图标不要凭印象拼 path ★（2026-09-27 少爷抓出）

给 UI 原型手写图标时，我把「设置」画成了 `circle r=3` + 八条放射线
（`M12 2v3 M12 19v3 M2 12h3 M19 12h3 …`）—— 那是**亮度 / 太阳**，
在所有设计系统里都不是设置。少爷一眼看出来：「为什么看起来像是个亮度图标」。

**规矩**：写 UI 原型里的图标，只用两类 ——
1. **抄官方 path 数据**（Material / Lucide 等，语义不会有歧义）
2. 或者干脆用文字标签，不手画

**永远不要"大概长这样"地拼 path** —— 图形语义画反比画丑严重得多，
用户会以为你实现的是另一个功能。同理适用于任何示意图标。
