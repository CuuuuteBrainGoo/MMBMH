## ⚠️ 用之前必须知道的三件事

**1. 这是一个「大模型识图」App，不是离线 OCR。**

它读票的方式是：把照片发给一个**多模态大模型**（就是能看图的那种 AI），
让模型把票面上的号码、期号、金额读出来。识别质量取决于模型的判断力 ——
拍得正、光线好，它就读得准。

**2. 你必须自己提供一个大模型 API Key，App 里不带任何 Key。**

仓库和安装包里**没有、也不可能有**能用的 Key。装完 App 的第一件事是去
设置页配一个你自己的 Key，否则「拍照录入」这条功能用不了（手填号码不受影响）。

好在这件事不贵也不难 —— **有免费的可以先试**，见下方
[「第一次配，选哪家」](#第一次配选哪家)。

**3. 不支持本地 OCR，也不打算支持。**

早期版本试过 MLKit / PaddleOCR 那套离线方案，最后砍掉了：

- 彩票票面是**热敏纸**，印得浅、易褪色、还有反光和折痕，传统 OCR 在这种图
  上错得离谱（尤其是红球蓝球数字挨在一起时）
- 而视觉大模型能靠上下文纠错 —— 它知道「双色球红球最大 33」，读到 38 会自己反应
  过来那是 3 和 8

换句话说：**离线方案认不准，才换成了要大模型的路子。**
所以「能不能不填 Key、纯本地跑」这个问题，答案是**不能**，这是设计取舍不是遗漏。

## 它做什么

| 功能 | 说明 |
|---|---|
| **拍照录入** | 拍票 → 发给多模态大模型读号码 → 填进账本。**需要自备 API Key**（[怎么弄](#关于-api-key)）。也支持不拍照直接手填 |
| **批量导入** | 一次选多张，逐张处理带进度，中断可恢复，结果自动分成「正常 / 重复 / 待确认」 |
| **本地对奖** | 官方接口只拿开奖号码，**对奖逻辑全在本地跑**，账目不上传 |
| **去重** | 每张实体票算一个指纹，同一张票重复录入会被拦住（防止重复记账） |
| **展示编号** | 每张票一个 `#12` 编号，越新数字越大，方便在提示和列表之间对号 |
| **过期提醒** | 兑奖期限 = 开奖日 + 60 天；国庆头 3 天、春节头 7 天内到期的自动顺延 |
| **统计报表** | 按彩种 / 按期号聚合，另有公益贡献合计 |
| **数据备份** | 导出 JSON 备份 / 从备份恢复，换手机不丢账 |
| **3 套皮肤 × 深浅色** | 墨金账本 / 支付宝 / 微信，各有白天黑夜两套 |
| **App 内帮助页** | 设置 → 帮助，讲了每个平台去哪申请 Key、三个输入框填什么、常见错误怎么排查 |

### 两条不通融的业务规则

1. **一二等奖金额必须人工确认后才计入盈亏。** 一、二等奖是浮动奖金，官方接口拿不到确定数字。程序不会替你猜 —— 它会显示「待确认」而不是当成 0 元（用 0 冒充一等奖是最糟的）。
2. **过期未兑永远是紫色 + 带负号。** 那是**永远拿不到的钱**，不是资产。

## 技术栈

- **Kotlin + Jetpack Compose**（全 Compose，无 XML 布局）
- **Room** 本地数据库，`app_settings` 是 key-value 表存设置
- **手写路由**（`sealed interface Route` + `when`），**不用** Navigation 库
  （依赖里虽列了 `navigation-compose`，但代码中一处未用，属历史遗留）
- **minSdk 26** —— 所以 `java.time` 可以直接用，不需要 desugaring
- **主题架构**：语义色走 `CompositionLocal` 下发，`LedgerColors.X` 是
  `@Composable @ReadOnlyComposable get()` 转发，所以加皮肤时**调用点一行都不用改**
- 皮肤（外观）× 深浅色（明暗）是**两个正交维度** → 3 × 2 = 6 套

### 目录结构

```
LotteryLedger/
  version.properties          ← 版本号唯一来源（gradle 读它）
  app/src/main/java/com/bro/lotteryledger/
    core/                     ← 纯逻辑：奖级规则、去重指纹、日期区间、统计口径
    db/                       ← Room 实体与 DAO
    net/                      ← 开奖接口（只拿号码）
    repo/                     ← 设置存储、备份编解码、Key 加密存储
    ui/                       ← Compose 界面
  app/src/test/               ← 单元测试（约 460 个）
UI Design/                    ← 网页原型，不参与编译
apk/                          ← 交付的安装包
```

## 编译

需要 JDK 17 + Android SDK（compileSdk 34）。

```bash
./gradlew assembleRelease
```

### 关于两个目录

开发时源码放在含中文和空格的路径下，而 `aapt2` 对这类路径不稳定，
所以编译时会把工程同步到纯 ASCII 路径的副本再编。
如果你 clone 到一个纯 ASCII 路径（比如 `C:\dev\LotteryLedger`），
**直接在这里编就行，不需要那套同步机制。**

## 版本号怎么管

唯一来源是 `LotteryLedger/version.properties`：

```properties
versionCode=16
versionName=1.6.3
```

- `versionCode` 每次发安装包 **必须 +1**（Android 靠它判断是不是新版本）
- `versionName` 加功能升 minor（1.4.0 → 1.5.0），只修 bug 升 patch

> 立这条规矩是因为踩过坑：连着迭代七八个版本，APK 里的版本号一直没动过。
> 根因是版本号散落在 gradle 文件里、每次打包没人检查 —— 这是机制问题，不是粗心问题。

## 关于 API Key

### 你需要自己去申请

App 不提供 Key，也**没有可以共用的 Key**。流程是：

1. 挑一个下面列的大模型平台，注册账号
2. 在它的控制台里创建一个 **API Key**（一串密钥，相当于你账号的钥匙）
3. 在 App 的**设置页 → 添加 AI 平台**里，选中平台 → 填 Key → 点「测试连通性」

「测试连通性」会**真发一张图**过去，通没通、错在哪一步当场告诉你 ——
比填完存下来再试省事得多。

### 第一次配，选哪家

App 支持 7 种接入方式，`设置 → 帮助` 里有逐步说明。**如果拿不定主意，看这两条：**

| | 推荐平台 | 为什么 |
|---|---|---|
| **只想零成本试通**（推荐先做这个） | **智谱** · `glm-4v-flash` | **免费**。注册最简单，够把「拍照识别」这条路走通。缺点是高峰期偶尔慢 |
| **想要识别最准、长期用** | **豆包 / 火山方舟** | 识别质量最好，就是这个 App 开发时一直用的那家。要实名 + 充值，且**必须先创建「推理接入点」**（新手最容易踩的坑） |

> **建议路径**：先拿智谱的免费模型跑通，确认整个流程你满意，
> 再决定要不要换豆包追求更好的识别率。**换平台随时换，账本数据不受影响。**

### 全部支持的平台

| 平台 | 预填模型 | Key 长什么样 | 计费 |
|---|---|---|---|
| **智谱**（推荐入门） | `glm-4v-plus`<br><sub>可换免费的 `glm-4v-flash`</sub> | `xxxxxxxx.xxxxxxxx`（中间一个点） | 有免费额度 |
| **豆包 / 火山方舟**（推荐长期） | `ep-xxxxxxxxxxxxxxxx`<br><sub>**填推理接入点 ID，不是模型名**</sub> | `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx` | 按量付费 |
| 腾讯混元 | `hunyuan-vision` | `AKIDxxxxxxxx` | 按量付费 |
| 百度千帆 | `ernie-4.5-turbo-vl` | `bce-v3/ALTAK-xxx/xxx`<br><sub>**不是 `sk-` 开头**</sub> | 按量付费 |
| 阿里云百炼 | `qwen-vl-max-latest` | `sk-xxxxxxxx` | 按量付费 |
| OpenAI | `gpt-4o` | `sk-xxxxxxxx` | 按量付费（需外网） |
| 自定义 | — | — | 任何 OpenAI 兼容服务 |

预填的**接口地址**都是官方地址，选中平台后 App 自动填好，通常不用改。
**模型名可以改** —— 想省钱就换成该平台更便宜的同系视觉模型。

### 三个最容易踩的坑

**① 豆包不能填模型名，要填「推理接入点 ID」**

火山方舟靠「接入点」把请求路由到具体模型，所以 `model` 那格要填 `ep-` 开头的 ID。
填模型名**有时候也能通**，但只要那个模型没在你账号里开通，就会报
`InvalidEndpointOrModel.NotFound` —— **这个措辞会让人以为地址写错了，其实不是。**

创建路径：方舟控制台 → 左侧「在线推理」→「推理接入点」→ 创建 → 选一个视觉模型 → 复制那串 `ep-` 开头的 ID。

**② 必须选「能看图」的模型**

纯文字模型（`gpt-4o` 之外的很多、`glm-4` 不加 `v` 的）**读不了照片**，会直接报错。
挑模型时认准名字里的 `v` / `vision` / `vl`。

**③ 有些平台要先把模型「开通」**

百度千帆尤其明显：不先在控制台「开通管理」里开通那个模型，接口会报「模型不存在」，
看起来像 Key 错了，其实是没开通。

### 花多少钱

按量计费，**读一张票大概一两分钱**。它不是订阅制，不用不花钱。

具体单价各家不同，且会调整 —— 以各平台控制台为准。想估算的话：
一张票的图大约几百到一两千 token，按视觉模型的常见价位算就是分这个量级。

> 这也是为什么砍掉批量重试那类功能 —— 每次重试都是真金白银。

### 你的 Key 和数据安全吗

| 问题 | 答案 |
|---|---|
| Key 存在哪 | **只在这台手机上**，用 Android Keystore（AES-256-GCM）加密 |
| Key 会上传吗 | **不会**。不走备份文件，重装 App 要重新填一次 |
| 什么被发到平台 | **只有那一张票的照片**。账本记录、金额、你的身份信息，一个字节都不离开手机 |
| 照片会留下吗 | **不会**。识别完立即删除，App 里找不到历史照片 |
| 对奖联网吗 | 联网，但**只去官方接口拿开奖号码**，你的账目不上传 |

### 给开发者：仓库里没有真 Key

源码里 `ProviderDefaults` 给新用户预填的都是**一眼假的占位符**
（如 `ep-xxxxxxxxxxxxxxxx`），让用户自己去控制台复制。

> 这里有个必须守住的规矩：**预填值会发给每一个装了这个 App 的人**，
> 所以里面绝不能出现任何具体账号的资源标识。
> 开发早期误填过一个真实接入点 ID —— 它不是密钥（没 Key 请求只会 401、花不掉钱），
> 但那是**别人的账号资源**，不该出现在别人的包里。已移除并重建了提交历史。

## 安装包

**推荐从 [Releases 页面](https://github.com/CuuuuteBrainGoo/MMBMH/releases/latest) 下载** ——
那里有版本号、更新时间和 Release Notes，点一下就能下。

仓库里的 `apk/` 目录**只保留当前版本**做备份（历史版本会被 `.gitignore` 排除）。
两个地方的文件是同一份，SHA-256 校验一致。

> 为什么历史版本不放仓库：git 会把这些二进制**永久留在历史里**
> （删文件也删不掉 `.git` 里的对象），仓库会一路变肥、clone 越来越慢。
> 所以策略是仓库只留最新版，历史版本走 Release 归档。

签名是 **Android 默认调试证书**（`debug.keystore`）：

- ⚠️ 换签名后**不能覆盖安装**，得先卸载（会清掉账本数据，**升级前先导出备份**）
